Work in ~/github/halo-ce-vita-spike/port-arm (decomp port, see [[halo-ce-vita-native-port]]).

- **Movie single-texel bug:** execute_draw computed the texture-scale uniform pointer before worker_build_record made the draw's fragment snapshot, and wrote into a snapshot shared by other draws. Fixed: per-draw copy of fragment buffer 1 whenever the snapshot's scale slots differ from the real scale. Affected every linear / render-target sampled draw (water, shadows, screen effects), not just Bink.
- **Movies on hardware:** sceKernelAllocMemBlock with an explicit alignment option on USER_MAIN_PHYCONT_NC returns 0x80020005 on the Vita (Vita3K accepts it). Now: phycont in whole MB with no option, CDRAM 256 KB-aligned fallback. BinkWait sleeps 1 ms when no frame is due. Intro plays full length at ~19 fps; conversion ~35 ms/frame is compute-bound (row buffer did not help).
- **Water speckle = minification aliasing** of the ripple bump map (game renders 4 levels into separate surfaces). render_target_chain + vgxm_target_create_chain put the levels in one linear mip chain (stride ALIGN(w,8)). Vita3K hides it (samples its own level-0 surface copy); HALO_CHAIN_BASE_LEVEL=3 proved aliasing. Unverified on hardware. The dark rectangle on b30's ocean is still unexplained.
- **Debug switches added:** HALO_TEX_FAST_ROWS, HALO_MOVIE_ROWS, HALO_TARGET_CHAIN, HALO_TEX_REUSE, HALO_MOVIE_AUDIO, HALO_NO_MOVIES (all default on except NO_MOVIES), HALO_TRACE_LINEAR.
- **Vita stops ~15 s after launch since ~00:40:** heartbeat.txt stops at beat 6 (12.9 s) for every launch, including the regenerated last-good build (dumps/elf/realtime1790832705.elf) and with movies skipped. No-sleep is on. Cause unknown and device-side; earlier launches tonight ran for minutes. Step tracing (HALO_TRACE_AFTER_MS, HALO_TRACE_FILES) showed the death is at ~14.8 s of process time whatever the frame (108 or 181), with HALO_NO_AUDIO=1, HALO_NO_MOVIES=1 or the old build alike; log.txt (stderr) empty; map cache files intact. Looks like the system ending the app: ask the user what the screen shows (error code, battery).

- **Worker texture checksum removed (01:30):** texel_checksum (per-frame checksum of every texture outside the tag cache, added Sept 30 for the font) was 10.5% of all Pi CPU; worker 8.3 -> 2.5 ms/frame on the Pi without it. Replaced by change marking: lock_level / LockBox (d3d8_resources.c) call vita_texture_locked (marks at lock + again at the next Present via vita_texture_locks_flush), and read_at in xbox_files.c marks file-read buffers (HALO_VITA only). HALO_TEX_CHECKSUM=1 restores the old check. Vita3K: movie, font, level select, a10 cinematic, b30 all correct. Not yet on hardware.
- Release builds now inline TAG_BLOCK_GET_ELEMENT (tag_groups.h); no Pi change measured. The Vita build runs with --lto off, so cross-file helpers stay calls there.
- tools/linux_build.py: gxm-null builds skip bink_vita.c (duplicate Bink symbols otherwise).
