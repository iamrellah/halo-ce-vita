**Harness (Sept 30 2026, port-arm):** `python3 configure.py --linux-cc <cc> --linux-d3d gxm-null --lto off --pgo off --portable --release` builds the Linux game with the Vita's Direct3D device (port/vita/platform/d3d8_gxm.c + nv2a_*_cg.c + vita_textures.c + vita_video.c) over port/vita/null/vgxm_null.c (answers vita_gxm.h/vita_host.h, draws nothing; shaders = Cg hash ids). sdl_platform.c has HALO_GXM_NULL conditionals next to HALO_VITA's. Works on x86 (clang-sdl32-reloc) and the Pi (clang-armhf). Run with HALO_GPU_STATS=1 HALO_DRAW_PROFILE=1: the "frame N:" line's "record ms/frame" and the "draw profile (us/draw)" line are the Vita's CPU-side render path measured without hardware. Scratch build trees live under the session scratchpad (pa-null = ARM, px-null* = x86); syncing port-arm into them with rsync must exclude build.ninja (it holds the configure args) and they must be reconfigured explicitly.

**Why:** the Vita's render on core 0 (25-57 ms) is the 30 fps wall and the user forbids touching the Vita until they say so; the Pi's headless GL build had no D3D cost at all in its 4.3 ms render.

**Numbers:** Pi (Cortex-A72 1 GHz) record ≈ 2.0 us/draw (key+textures 0.6-0.7, fragment uniforms 0.6, vertex constants 0.5) + worker 1.5 us/draw, ≈ 2 ms/frame of a ~5.5 ms render; the Vita measured 21 + 21 us/draw for the same code (10-14x, vs ~5x CPU ratio) → the Vita's extra is uncached ring writes (~1 MB/frame of uniform snapshots: ~700 vertex snapshots of ~1.5 KB, 320 fragment of 528 B), the cold 1044-byte render_command entries (COMMAND_RING 6144 = 6.4 MB), and vita_host_time_us syscalls (HALO_DRAW_PROFILE adds 9 per draw - compare record ms with it off). Model shaders with relative constant reads snapshot up to register 191 (nv2a_vertex_shader_constant_range).

**Profiling tools:** tools/profile_symbolize.py BINARY SAMPLES [--addr2line <cross addr2line>] [--lines FUNC] [--callers FUNC] symbolizes HALO_PROFILE=<file> HALO_PROFILE_SECONDS=<s> sample files (posix_profile.c, pc+lr on ARM). tools/frame_timing_compare.py LOG... compares runs on the game-tick axis (window indices differ between builds with different fps). Never combine gdb with HALO_PROFILE (SIGPROF under gdb ends the run at once). No perf on this machine or the Pi.

**Findings:** epoch hooks (render_epoch.c) were ~5% of all CPU on the Pi and halo_epoch_end (byte scan of every marked array's slots at the join) 0.5-6%; fixed Sept 30 13:00 with a slot index in data_array's padding bytes 38-39 (MARK_SLOT) and a mark log (O(marks) sweep) - "other" dropped 0.1-0.2 ms/frame on the Pi. -fmax-type-align=1 removal: crashes at once (hs.c script floats); removing it only for hot dirs (clang-armhf-noalign-hot) survived 4 min, tick -5%, render unchanged - not worth it on the Pi. Pi run-to-run noise: render ±8% between identical runs (base1 3.92 vs base2 4.23 ms), tick stable; use several runs or in-process counters.

**D3D record changes (Sept 30 13:00-13:35, all in port-arm, verified x86 harness + Pi harness + Vita3K screenshots):** (1) vertex constants split into six uniform buffers by rewrite rate (vita_xgpu.h VITA_VC_*: A 0..11 per view, B 12..16 per part, C1 17..27 lighting per object, C2 28..59, D 60..183 node matrices copied up to the extent written this/last frame, E 184..191); relative reads (a0) stay in their base's chunk (node matrices from 60/61/62, model point lights from 17/18/19); uniform bytes 2185 -> 397 KB/frame in the b30 cutscene. (2) immediate-mode vertices carry only the input registers the program reads (nv2a_vertex_shader_input_mask): 172 -> 28 KB/frame. (3) fragment uniforms split A (0..17 combiner constants) / B (18..32) into BUFFER[0]/[1]. (4) per-stage texture description cache, cached small/depth surface tests, worker blend naming by shader id. Stats line now prints copied bytes by kind + uniform KB; HALO_GPU_STATS=1 also logs each vertex shader's chunks and the per-frame constant-write histogram ("constant writes per frame"). Vita3K image check: install eboot into ~/.local/share/Vita3K/Vita3K/ux0/app/HCEV00001/, `cd ~/vita3k/ubuntu && DISPLAY=:1 ./Vita3K -f -w -l 1 -r HCEV00001`, 100 s, shots in ux0/data/haloce-vita/shots (env.txt HALO_SCREENSHOT_EVERY=300), reference shots of the 12:30 build in shots-ref; frames are not bitwise comparable (game time drifts), compare by eye. The Vita eboot with all of it: port-arm/build/vita/eboot.bin (13:33); the untouched 12:30 build is build/vita/eboot-1230.bin. NOT run on the Vita.
